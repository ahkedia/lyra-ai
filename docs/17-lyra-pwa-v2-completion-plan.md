# Lyra PWA v2 completion plan

## Purpose

Finish the agreed iPhone-first Lyra product without mistaking a partially styled
shell for the finished experience. This plan supersedes implementation priority
where it differs from `16-lyra-pwa-v2-technical-spec.md`.

## Product contract

The installed PWA has exactly three primary destinations:

1. **Lyra** is the default. It is one durable, chronological personal stream,
   equivalent in conversational usefulness to Telegram but with validated,
   source-aware native components.
2. **To Do** follows the useful interaction model of Apple Reminders, backed by
   the existing Notion reminder adapter. It never reports a provider mutation as
   complete until Notion confirms it.
3. **News** is a source-forward, Perplexity-like reading feed. The morning brief
   creates the stream event and the dated News brief in one canonical write.

The design language is mobile-only, neutral, and ChatGPT/Codex-inspired: SF Pro,
white/black/gray surfaces, blue primary controls, compact user bubbles, open Lyra
responses, and no dashboard-card treatment. The earlier green accent token is
obsolete for this product direction.

## Audit of the current diff and working tree

The working-tree code change is a valid correctness fix, not a product-direction
implementation:

| Change | Assessment | Required follow-up |
|---|---|---|
| Structured-question option IDs, version, HTTP statuses | Correctly prevents valid radio choices from being rejected and makes conflict/expiry visible to the client | Add HTTP-level 409/410/422 coverage and implement actual resumed Lyra work after answer |
| Three-tab shell, renderer, stream, To Do and News code | Present, but incomplete against the product contract | Finish the feature gaps below before visual tuning is accepted |
| Compiled `app/public/assets/main.js` | Generated by the current frontend build | Keep it in the same scoped commit as its TypeScript source |

The following are currently missing or incomplete:

- Lyra has no real feed pagination, unread marker, new-message control, scroll
  retention, or bounded rendered window.
- A settled question is marked `queued`, but there is no exactly-once worker that
  resumes the underlying Lyra/OpenClaw task and returns the result to the stream.
- Scheduled delivery polls OpenClaw runs, but private cron prompts have not been
  migrated to emit the `lyra-ui` structured envelope. Morning News cannot be
  treated as complete until a real run creates its source-backed brief.
- The To Do UI supports create, edit, and complete, but not the complete supported
  lifecycle: reopen, list/priority fields when mapped, mutation version conflicts,
  and durable offline mutation replay.
- News supports basic read/save/detail/share, but its local mutations do not queue
  durably offline and the feed needs a real brief, stale state, source clustering,
  and final mobile hierarchy verification.
- Settings lacks sign-out and a complete, user-readable source/delivery health
  view. Voice capture has upload but not its usable history/playback surface.
- Browser E2E, visual baselines, agent evaluations, cron reconciliation, physical
  iPhone acceptance, and the 14-day PWA-first period remain outstanding.

## Delivery sequence

### Phase A: Stabilize the canonical backend

1. Land the structured-question fix with unit and HTTP-level conflict, expiry,
   validation, and retry tests.
2. Replace the current whole-state persistence boundary with repositories backed
   by the existing v2 Postgres migration: events, actions, questions, deliveries,
   push subscriptions, News state, and sessions. Keep the file store as an
   emergency local mirror only.
3. Build the question continuation worker. Claim a queued answer once, resume the
   private conversation context, append its result as a canonical assistant event,
   and record terminal failure without fabricating a reply.
4. Add the privileged cron reconciliation endpoint and root-side reconciling
   script. It reports only job/run/status metadata and uses the same cron idempotency
   key as normal delivery.

**Gate:** restart, duplicate request, competing answer, expired answer, failed
provider, and missed cron tests all preserve a single trustworthy record.

### Phase B: Finish the three tab behaviours

1. **Lyra:** add cursor pagination (40 per request), chronological reading order,
   unread/new-message control, scroll retention, pending/offline states, grouped
   automation messages, and streaming-safe finalization.
2. **To Do:** complete/reopen, quick add, edit, source-supported flag/list/priority
   fields, versioned mutations, offline replay ordering, and explicit conflict and
   provider-failure recovery. Hide unsupported fields rather than pretending they
   work.
3. **News:** use a real morning brief, keep last valid brief on failure, cluster
   sources, preserve durable read/save state, queue those safe mutations offline,
   and ensure story detail exposes title, publisher, URL, publication time, share,
   and stable-ID Ask Lyra hand-off.
4. **Settings and share:** add sign-out, source/delivery health, queue retry,
   passkey status, notification test, theme, version/last sync, plus native share
   for stream events and stories with clipboard fallback.

**Gate:** each tab is useful with current production data, works after relaunch,
and never claims a failed external mutation succeeded.

### Phase C: Make scheduled output genuinely rich

1. Update private OpenClaw cron instructions to retain readable prose and add an
   optional fenced `lyra-ui` envelope when a component improves comprehension.
2. Convert the morning brief first: `briefing` plus valid `news_brief`, sources,
   freshness, and generated timestamp.
3. Convert recurring health, workout, reminder, and check-in jobs to the smallest
   appropriate block types such as checklist, callout, task snapshot, chart, or
   question form. Plain text remains the safe fallback.
4. Keep all Telegram fallback messages self-contained, without Mini App links or
   web-app buttons. The PWA remains unframeable.

**Gate:** a forced non-destructive morning run produces exactly one Lyra event,
one News brief, one eligible push delivery, and source chips that resolve.

### Phase D: Mobile design completion

1. Consolidate all UI into the neutral blue token system. Remove remaining green,
   extra font treatments, dashboard cards, and decorative labels.
2. Verify the component gallery against every golden fixture: text, lists,
   checklists, tables, charts, images, media, files, sources, actions, briefing
   sections, task snapshots, questions, and code.
3. Add screenshot baselines for iPhone SE, iPhone 15/16, and wide iPhone viewports.
   Review the Lyra stream, To Do, News, sheets, composer, offline state, and every
   rich component variant.
4. Verify tap targets, keyboard-safe composer/tab bar, outside-tap sheet dismissal,
   reduced motion, dark mode, and empty/stale/error states.

**Gate:** no hamburger/sidebar, no mixed visual system, and no unreviewed visual
regression at the three mobile viewports.

### Phase E: Production migration and acceptance

1. Deploy in small, reversible commits to both canonical Hetzner checkouts.
   Run migration and targeted smoke tests before enabling each switch.
2. Test PWA launch, sign-in, Home Screen installation, Face ID, voice capture,
   push deep links, offline launch, queued changes, and touch behavior on the
   physical iPhone.
3. Verify all active crons are canonical PWA events, Telegram fallback is complete
   and link-free, and no traffic reaches the retired Mini App path.
4. Run a 14-day PWA-first shadow period. Measure delivery, capture, action success,
   push success, latency, and missed commitments before declaring messaging
   emergency-only.

**Gate:** every definition-of-done item in section 22 of the technical specification
is evidenced. The 14-day observation and physical-device checks require Akash's
real-world use, so they cannot be simulated by implementation work.

## Working rules

- Commit only Lyra-scoped files. Preserve the unrelated untracked wiki/content
  work already in this repository.
- Never print, commit, or copy host secrets, Notion identifiers, Telegram chat IDs,
  or private cron configuration.
- Persist before any push or fallback delivery. Display an explicit unavailable or
  stale state rather than raw tool output or fabricated success.
- Do not declare the migration complete after a browser-only demo. The physical
  iPhone and shadow-period gates are release evidence, not optional polish.
